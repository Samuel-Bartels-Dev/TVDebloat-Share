# Independent webOS Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. Steps use checkboxes.

**Goal:** Add independent webOS discovery, profiles and safe launcher planning to TVDebloat.
**Architecture:** Explicit platform dispatch keeps Android behavior separate. A fixed-command SSH/Luna client feeds normalized discovery; a separate profile and plan engine binds proposed ordering changes to identity and observed state.
**Tech Stack:** Python 3.11+, standard library, existing OpenSSH; unittest.
**Spec:** ../specs/2026-10-28-webos-design.md

## Global Constraints
- No Glasshouse runtime dependency, no added Python dependency, no live TV calls during development.
- No rooting, daemon installation, firmware change, reboot, uninstall or service disable.
- Unknown firmware/capability is read-only. No profile may grant a write capability.
- Retain Android default behavior; reject cross-platform profiles before connection.

## Review Focus
- Malformed or false Luna responses must never become successful empty inventories.
- Bookmarks and HDMI launch points may share app IDs: preserve unique launchPointIds.
- A missing webOS platform version cannot be guessed from firmware.
- An SSH error may contain private data: export only a generic operation error.
- A timeout after a move leaves uncertainty: journal before sending; refuse blind recovery.
